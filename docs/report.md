## 1. Краткое описание продукта
«Яндекс Почта» — веб-сервис электронной почты для получения, отправки, хранения и организации сообщений. Для тестирования выбраны модули авторизации, работы с письмами, поиска и фильтрации, папок и правил, вложений и выхода из аккаунта.

## 2. Карта модулей и подмодулей
- **1. Авторизация:** вход по логину и паролю; восстановление доступа; выход из аккаунта.
- **2. Работа с письмами:** просмотр входящих; создание и отправка письма; ответ и пересылка; удаление; архивирование; черновики.
- **3. Поиск и организация:** поиск по отправителю/теме/тексту; фильтры; папки; метки; правила автоматической обработки.
- **4. Вложения:** прикрепление файла; просмотр; скачивание; проверка ограничений размера.
- **5. Настройки:** настройки интерфейса; управление правилами; настройки безопасности и аккаунта.

## 5. Функциональные требования
- **REQ-01.** Система предоставляет форму входа и проверяет учётные данные.
- **REQ-02.** Система отображает почтовый ящик после успешной авторизации.
- **REQ-03.** Пользователь может открыть письмо и просмотреть его содержимое.
- **REQ-04.** Пользователь может создать письмо с адресатом, темой и текстом.
- **REQ-05.** Система проверяет корректность адреса получателя.
- **REQ-06.** Пользователь может отправить письмо и увидеть подтверждение отправки.
- **REQ-07.** Пользователь может сохранить письмо как черновик.
- **REQ-08.** Пользователь может ответить на письмо или переслать его.
- **REQ-09.** Пользователь может переместить письмо в корзину или архив.
- **REQ-10.** Пользователь может искать письма по ключевым словам.
- **REQ-11.** Пользователь может применять фильтры к списку писем.
- **REQ-12.** Пользователь может создавать личные папки и перемещать в них письма.
- **REQ-13.** Пользователь может создавать правила автоматической обработки писем.
- **REQ-14.** Пользователь может прикреплять файлы к исходящему письму.
- **REQ-15.** Система сообщает об ошибках загрузки и превышении допустимого размера вложения.

## 7. Тест-кейсы
Подготовлены пять тест-кейсов. Для реального прогона используйте только специально созданный тестовый аккаунт.

### TC-01 — Успешный вход с корректными данными
- **Приоритет:** Высокий; **связанные требования:** REQ-01, REQ-02; **Use Case:** UC-01.
- **Предусловие:** Есть тестовая учётная запись; пользователь вышел из аккаунта.
- **Шаги:** 1) Открыть страницу входа. 2) Ввести корректный логин. 3) Ввести корректный пароль. 4) Нажать «Войти».
- **Ожидаемый результат:** Форма отображается; логин введён; пароль скрыт; открыт почтовый ящик.

### TC-02 — Отказ во входе при неверном пароле
- **Приоритет:** Высокий; **связанные требования:** REQ-01; **Use Case:** UC-01.
- **Предусловие:** Есть зарегистрированная тестовая учётная запись.
- **Шаги:** 1) Открыть страницу входа. 2) Ввести существующий логин. 3) Ввести неверный пароль. 4) Нажать «Войти».
- **Ожидаемый результат:** Показано сообщение об ошибке; почтовый ящик не открыт.

### TC-03 — Отправка письма на корректный адрес
- **Приоритет:** Высокий; **связанные требования:** REQ-04–REQ-06; **Use Case:** UC-03.
- **Предусловие:** Пользователь авторизован; доступен тестовый адрес получателя.
- **Шаги:** 1) Открыть создание письма. 2) Ввести корректный адрес. 3) Указать тему и текст. 4) Нажать «Отправить». 5) Открыть «Отправленные».
- **Ожидаемый результат:** Адрес принят; тема и текст отображаются; показано подтверждение; письмо присутствует в «Отправленных».

### TC-04 — Поиск письма и уточнение результатов фильтром
- **Приоритет:** Средний; **связанные требования:** REQ-10, REQ-11; **Use Case:** UC-05, UC-06.
- **Предусловие:** В ящике есть письма с известной темой и вложениями.
- **Шаги:** 1) Открыть почтовый ящик. 2) Ввести часть известной темы. 3) Запустить поиск. 4) Применить фильтр «С вложениями».
- **Ожидаемый результат:** Показаны соответствующие письма; после фильтра остаются письма с вложениями.

### TC-05 — Работа с вложением в письме
- **Приоритет:** Средний; **связанные требования:** REQ-14, REQ-15; **Use Case:** UC-09.
- **Предусловие:** Пользователь авторизован; подготовлены допустимый и заведомо слишком большой тестовые файлы.
- **Шаги:** 1) Открыть создание письма. 2) Прикрепить допустимый файл. 3) Проверить отображение. 4) Попытаться прикрепить файл выше лимита.
- **Ожидаемый результат:** Допустимый файл прикреплён и отображается; для файла выше лимита показана ошибка.

### TC-06 — Сохранение черновика
- **Приоритет:** Средний; **связанное требование:** REQ-07; **Use Case:** UC-04.
- **Предусловие:** Пользователь авторизован.
- **Шаги:** 1) Открыть создание письма. 2) Ввести тестовый адрес и часть текста. 3) Закрыть форму штатным способом. 4) Открыть «Черновики».
- **Ожидаемый результат:** Черновик присутствует в папке; введённые данные сохранены.

### TC-07 — Создание папки и перемещение письма
- **Приоритет:** Средний; **связанное требование:** REQ-12; **Use Case:** UC-07.
- **Предусловие:** Пользователь авторизован; есть тестовое письмо.
- **Шаги:** 1) Создать папку с уникальным тестовым названием. 2) Выбрать тестовое письмо. 3) Переместить его в созданную папку. 4) Открыть папку.
- **Ожидаемый результат:** Папка создана; выбранное письмо отображается в ней.

### TC-08 — Создание правила обработки
- **Приоритет:** Средний; **связанное требование:** REQ-13; **Use Case:** UC-08.
- **Предусловие:** Пользователь авторизован; доступен тестовый отправитель и тестовая папка.
- **Шаги:** 1) Открыть настройки правил. 2) Задать условие по тестовому отправителю. 3) Выбрать действие перемещения в тестовую папку. 4) Сохранить правило. 5) Проверить список правил.
- **Ожидаемый результат:** Правило сохранено и отображается в списке.

### TC-09 — Выход из аккаунта
- **Приоритет:** Высокий; **связанное требование:** REQ-01 (завершение пользовательской сессии); **Use Case:** UC-10.
- **Предусловие:** Пользователь авторизован.
- **Шаги:** 1) Открыть меню аккаунта. 2) Выбрать «Выйти». 3) Проверить отображаемую страницу.
- **Ожидаемый результат:** Пользователь возвращён к странице входа; закрытая сессия не предоставляет доступ к почтовому ящику.

## 9. Набор тест-кейсов и его тип
Набор выбран **последовательным**, поскольку сценарии выполняются в логичном порядке: вход → работа с письмами → поиск/фильтрация → вложения → выход. По характеру данных набор **обобщённый**: тесты используют разные письма и тестовые файлы, а не один неизменный объект. Каждый тест-кейс должен иметь подготовленные предусловия.

## 10. Жизненный цикл тест-кейса TC-03
| Состояние | Когда наступает | Что происходит дальше |
|---|---|---|
| Создан | Тест-кейс составлен | Запланирован |
| Запланирован | Включён в план тестирования | Выполняется |
| Выполняется | Тестировщик выполняет шаги | Пройден успешно / Провален / Заблокирован |
| Пройден успешно | Фактический результат совпал с ожидаемым | Закрыт |
| Провален | Результат отличается от ожидаемого | Создаётся дефект |
| Заблокирован | Нельзя продолжить из-за недоступности сервиса/тестового аккаунта | Повтор после устранения причины |
| Требует доработки | Изменились требования или обнаружена ошибка в тесте | Создан / Запланирован |
